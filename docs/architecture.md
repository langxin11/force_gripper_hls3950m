# 总体架构

控制核心使用标准 C++17，通过抽象的 `ServoBus` 访问舵机；具体协议、未来控制板实现和上位机接口与控制逻辑解耦。这样可以在无硬件环境测试状态机，也能在更换通信方案时保留控制逻辑。

## 分层

| 层级 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| 机械与电气 | 安装、传动、供电、接线和散热 | 控制协议和上位机业务逻辑 |
| 舵机总线适配 | HLS3950 帧、寄存器、超时和单位换算 | 夹爪状态机和 ROS 接口 |
| 控制核心 | 双电机协调、限幅、故障处理和后续力控 | 串口驱动和具体寄存器地址 |
| 控制板应用 | 调度控制周期、解析主机命令、发布状态 | 机械参数的隐式硬编码 |
| Python SDK | 稳定的初始化、使能、位置和状态 API | 直接访问舵机总线 |
| ROS 适配 | ROS 话题、服务和参数桥接 | 重复实现控制算法 |

## 数据流

```text
Python/ROS
    | 高层 JSON Lines 命令
控制板应用
    | 调用控制 API
GripperController
    | ServoBus 接口
HLS3950 总线适配
    | 半双工串口
两台 HLS3950
```

命令格式和错误语义详见[主机通信协议](host-protocol.md)。

## 安全边界

- 默认输出关闭，初始化成功后才允许使能。
- 输出在控制核心统一限幅，初始上限为额定范围的 25%。
- 任一电机通信失败时，两侧同时停止并关闭扭矩。
- 故障不能靠下一条普通运动命令自动清除。
- 真机测试必须脱离夹爪传动机构或设置机械限位保护。

当前台架由电脑经 URT-1 运行 `vassar-feetech-servo-sdk==1.5.0`，直接控制 HLS3950。
上图中的 C++ `ServoBus` 数据流对应未来板级控制路线；具体 MCU 或控制板尚未选定。
